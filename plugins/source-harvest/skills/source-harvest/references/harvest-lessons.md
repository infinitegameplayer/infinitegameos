# Source Harvest lessons

Dated lessons from real harvests, grouped by the step they sharpen. Each one changed how a later harvest ran. The sources are described rather than named: the lesson travels, the source stays its author's.

## Reading the source

**A prior read is a claim about a source's size.** An earlier read called one pack three files, and the guide it skipped held most of the harvest. When a prior read names a document it did not open, open that document first.

**A consult is a synthesis: read the primary behind every figure a plan will lean on.** A summary can carry the right figure and miss the nuance in the source. Read the primaries raw before the figure sets anything.

**A prior summarized read is a layer, never the source.** A summarizing fetch is a claim about a page or a book. Read the raw pages even when a good read exists, and check quotes against the book or page itself, not against a scan or summary of it. In one harvest, raw pages corrected three claims of an earlier read and held its strongest missed pattern.

**A corpus pulled by one key needs a second query as its control.** A pull by sender address can truncate and still look complete. Pull by address and by display name, and brief readers only when the two counts agree.

**When the source is a course, the student side is part of the source.** Replies often hold only cover notes while the real work sits in attachments. Fetch your own submitted work and the instructor's marks on it before calling them secondary.

**Search your own archive for past use of the source.** Before adapting a teaching, search your old notes and migrations for where you already applied it. The result can combine the source with your earlier work in a way neither would give alone.

**In a teaching text, the hidden layer lives in the revisions.** When a source teaches, ask readers to list where it corrects itself, and read the list as the message. If every correction points the same way, that direction is the author's intent.

**On a website, the source is the raw HTML and the page's own script files, never a summarizing fetch.** A summary cannot tell a page a visitor sees from a page an agent sees. Fetch the raw HTML, count forms and inputs in the server-rendered markup, then read the script files that load afterward. When a finding says something is absent, grep the raw artifact for it before writing the sentence.

## Classifying

**A telemetry off switch is a claim: read the code path it guards.** A docs page and a setting can both say telemetry stops while one call still fires with the switch set. When a harvest records a tool's telemetry, grep for the switch, then read every call that still runs when it is set. The doc page is the vendor's claim. The code is the instrument.

**When the source is a science, validate each claim cold.** Gather readers by angle, then give each claim a validator told only to refute it and told nothing of your system. Brief the validator with the claim as plain fact. Your own words leak intent into a brief ("deliberately", "orderly", "only"), and the validator should strip it back out. Expect most claims to come back qualified.

**A source built on the same floor as yours is a mirror, and the divergence is the finding.** When most components confirm what you already run, look for the one place the source chose differently and ask whether you have ever written down why you chose your way.

**When the domain is foreign, a harvest that mostly confirms is a result.** Most components may turn out to be rules you already hold. Ask of each strong pattern where your system would already have fired it, and count a match as evidence your rule holds. Enrichments come from the few places a mature source is ahead of you.

**A rhyme between two systems on the same harness may be the harness.** When a source runs the same tools you run, check a shared pattern against those tools' defaults before crediting either side with it. The tool can be shared by both parties, not only by the source.

**Read hardware as a question about the job it does.** A source's bill of materials may answer a need that something you already own answers. Name the job, then look for what already does it.

**The best landings are gaps you have already written down.** Before classifying, search the target surfaces for your own open questions (planned sections, forward notes, paused brainstorms, gap flags) and land findings there first. Each one has been waiting for exactly this shelf.

**A source that promises results should name what would count against it.** Many fail the premise check in one way: every miss has a supplied cause and no result is allowed to count against the method. If the source does not say what would count as the method not working, the adoption carries that count: a guess written before and a miss tally after.

## Verifying the report

**A quote checker passes a misattributed quote.** It confirms that the words occur, not who said them. When a report credits a person with a line, read the line at its source to confirm the speaker. Take every count in the summary from the disposition table by tool, never by eye: one harvest's tally of "covered" items was off by one until a tool counted the rows.

**A quote can be verbatim and still misused.** A checker confirms the words occur. It cannot confirm what the words are for. When a figure from a source sets a threshold in your plan, quote the sentence that says what the figure is for, not only the figure.

**A directory source is only as wide as the checker's extension list.** A checker that reads only some file types can drop the rest in silence, and true quotes then read as missing. Make your checker name every file it skips. When quotes from a docs folder go missing, look for a skipped-files line before calling a quote wrong.

**A correction of a worker is a claim too.** Before writing that a worker got something wrong, open the line the worker cited. In one harvest the orchestrator's correction was itself wrong, and the reader had been right.

**When a harvest holds both the citing source and the cited one, check the citation at the cited text.** A secondary source's attribution is a claim, and so is your own summary of a source.

**Count every figure in the report with a tool before presenting it.** One report's word total, summed by eye, ran a quarter low. One script's count disagreed with two other tools for a cause never found, so cross-check a surprising count with a second tool. OCR splits long quotes at line-end hyphens, so a checker misses correct quotes from a scan: quote OCR text in fragments that fall within one line.
